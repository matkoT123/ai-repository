# J&T mToken Android (jt-mtoken-android)

Mobile token app for J&T Banka (SK `jtsr`, CZ `jtcz`) plus an Asseco demo tenant: activation, transaction signing, QR login, offline OTP, messages, security (Promon Shield, ThreatMark, cert pinning, root detection). ## Stack
Package `com.ace.factor`; app ids `com.jtsr.mtoken`, `com.jtcz.mtoken`, `com.asseco.mtoken`. Kotlin + Java, Java 17 target, Hilt, Retrofit/OkHttp, XML + Compose, Firebase, Spongy Castle, ZXing, Paging 3. Min SDK 28.
Flavor dimensions: bank (`asseco`, `jtsr`, `jtcz`) x environment (dev, itp-a, itp-b, int, devint, uat, ref, prod) x shield (`shielded` Promon, `unshielded`).
CI: GitLab, CycloneDX SBOM to Dependency-Track. Trust stores: `RefreshTrustStores.java` / `refresh_trust_stores.py`.
The app does not use MFLL; it has its own full copy of the logic. The new SDK replaces it.

## SDK migration rules
- No temporary or bridge solutions. Nothing ships until all blockers are closed, so fix properly, also in the SDK (we own it). The open question is only scope/budget approval (Jakub Tropp).
- The app consumes `com.mtoken:sdk:3.0.8` from mavenLocal; republish after SDK changes (see `build-env.md`).
- Compare every suspected regression with `main` (version 03.86) on the same environment before reporting.

## Durable gotchas
- Promon Shield config: `config-jtsr.xml` / `config-jtcz.xml` control `exitOnRooting` and `exitOnRootingURL` (bank security pages). Shielder binaries in `promon/shielder/`. Shield upgrades take about 10-12 h including device tests with root detection.
- Deactivation endpoint is `DELETE mtokenlib/v1/unregister` with header `SEZAM_ACCESS_TOKEN_NEW`; the old `DELETE /mtoken` returned 403 non-JSON.
- JTSRAUTH-7554 / ASB-1634 (device migration loses the AndroidKeyStore key while activation flags survive) is fixed here; the same bug still exists in `jt-mfll-android` (see `mtoken-sdk.md`).
- Jira texts for the bank are reviewed strictly by moravec; follow `rules/writing-sk.md` exactly.
