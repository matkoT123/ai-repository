# MODULES - Adit reusable backend modules

In-house platform of Spring Boot microservices (package `sk.aconsulting.*`) used as the base for new Adit products (ROSA, CHATBOT, new Bookadlo). Listed on the CV as "Reusable backend modules: authentication and authorisation, notifications and audit logging".

## Status
Inactive since autumn 2025. Last commits: uaa-be and codelist-be 2025-10-09 (BKDL-470), uat-stack 2025-10-22.

## Stack
- Java 23, Spring Boot 3.4.1, Maven wrapper, PostgreSQL, Flyway, MapStruct + Lombok, springdoc OpenAPI, Spring Boot Admin client, RabbitMQ 4.0, Redis 7.
- Inter-module clients generated by `openapi-generator-maven-plugin` from `api/<other-module>.yaml` specs checked into each repo.
- Stack: Keycloak 26.1, nginx 1.27, Portainer, Loki 2.9 + Grafana, Alfresco Community 23.4 (doc-be storage), Elasticsearch (chatbot).
- Images: `dev.adit.sk:5000/aconsulting.sk/<module>-be[-uat|-bookadlo-prod]:latest`. Not in local folders: doc-be, modules-fe, rosa-fe, chatbot-fe, spring-admin, rosa-wiki.

## Build / run
- Per module: `build.bat` = `mvn clean install -DskipTests`; `compose.bat`/`compose.sh` = `docker compose up -d` for local Postgres/RabbitMQ/Redis.
- Install `common-be` first (other modules depend on the SNAPSHOT).
- Server: `reload.sh` pulls all images and runs `docker compose up -d`. `compose_no_be.yaml` = infra only.
- Spring profiles per deployment: `application-uat.yaml`, `application-bookadlo-prod.yaml`.

## Worth reusing
- Same package layout in every module: `client, configuration, controller, data, exception, message, sample, service`.
- Event-driven sync of reference data between services over RabbitMQ (common-be `Sync*` classes).
- `sample` package seeds demo data. Error messages localised in `messages/error-messages[_sk].properties`.
- audit-be was the reference for Balansee's `balansee-audit` (see memory `D--ACONSULTING-PROJECTS-MODULES-audit-audit-be`).
